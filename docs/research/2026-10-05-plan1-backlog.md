- Done: The dirty-state wording of `CRASHED` (spec section 8). No Plan 1 code sets `dirty`. (4b0c783: `LOST_CHANGES` at `world-machine-session.ts:35`, used at :122 and :315-317; spec section 6 sets `dirty`.)
- Decided (by design, from the d551e8e review): the internal-error result from `respond()` is plain text, `Internal error in <tool>; see the server log`, not the section 8 JSON payload. Section 8's payload requires a `code: ErrorCode`, and no code fits a server bug (`START_FAILED` is reserved for startup, `UNEXPECTED_OUTPUT` for parser mismatches); an `INTERNAL_ERROR` code would be a spec change to section 8 and to the `ErrorCode` union. The result is still `isError: true`, and only bugs reach this path, so a client gains nothing from parsing it. Revisit only if a client needs a machine-readable code for it.
