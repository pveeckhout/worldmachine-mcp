# User-built catalogs, plan 1 of 3: catalog store and kinds

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans (reference: ~/.claude/superpowers-refs/executing-plans.md) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server loads catalogs from a local folder per build beside the shipped ones, picks one per build in the
spec's order, treats conflicts of a sample-derived catalog as warnings, and says in `get_device` and `plan_graph`
which catalog it used.

**Architecture:** The catalog kind (strict or sample-derived) becomes a field of the port-type catalog JSON. A pure
domain module ranks candidate catalogs. A file-system adapter reads the local folder once at startup, with the same
validating reader a capture will use before installing (plan 3). `WorldMachinePortTypes` and the enum attachment
receive the merged lists; `checkWireTypes` splits its findings by kind.

**Tech Stack:** TypeScript 7 (ESM, `.js` import suffixes), Node >= 22.12, vitest 5, biome, zod 4 for MCP schemas.

**Spec:** `docs/superpowers/specs/2026-11-17-worldmachine-mcp-user-built-catalogs-design.md` (D4, D5, the load half
of "Safety of catalog files", and the Catalog aggregate of the domain model). Plans 2 (corrections) and 3 (capture)
build on this one.

## Global Constraints

- No new runtime or dev dependencies.
- The package ships only `dist` (`package.json` `files`); nothing at runtime reads `scripts/` or `test/`.
- No part of the product or its scripts reads, disassembles, or extracts World Machine's binaries or install files.
- Hexagonal layout as in the repository: domain in `src/domain`, ports one per file in `src/application/port/{in,out}`,
  adapters in `src/adapter`. Commands and queries never share a port.
- Catalog files are never edited by hand; the shipped JSON files are regenerated by their scripts.
- Lookup per build, first match wins: shipped strict, local full, shipped sample-derived, local short (D4).
- A catalog file that fails to parse at startup is reported (log and tool response) and ignored; the build then
  behaves as uncatalogued.
- Commits: Conventional Commits, subject at most 72 characters, a short message, no AI attribution.
- `npm test` runs the build first (`pretest`); `npm run check` runs typecheck, lint, tests, and fixture checks.

## Review Focus

1. A local folder named `4071` holding a catalog whose `build` is 4069: ignored with a problem, never used for 4071 or
   4069 (Task 4 test `rejects a catalog whose build differs from its folder`).
2. A local `port-types.json` for build 4067 (a user copied files around): never used, since shipped strict wins
   (Task 2 test `shipped strict beats every local catalog`).
3. A catalog directory that does not exist yet (first run): no problem reported, nothing loaded (Task 4 test
   `reports nothing when the catalog folder is missing`).
4. A JSON file whose classes reference an id the catalog lacks: rejected at load, not at the first `get_device`
   (Task 4 test `rejects a port type whose class is missing`).
5. A plan on a sample-derived catalog with both a loop conflict and a type warning: `apply_graph` still refuses for
   the loop (Task 6 test `apply refuses a loop conflict even when type findings are warnings`).

**Files:**

**Interfaces:**
- Produces in `catalog-reader.ts`:
  - `export function readPortTypeCatalog(json: unknown): PortTypeCatalog` (throws `Error` naming the first fault:
    not an object, `build` not a positive integer, `kind` neither `strict` nor `sample-derived`, a type without `added`/`inputs`/`outputs`
    arrays, a port whose `class` is not in `outputClasses` (outputs) or `inputClasses` (inputs), an input class
    naming an output class that does not exist).
  - `export function readEnumCatalog(json: unknown): EnumCatalog` (throws on a non-integer `build` or a type
    without a `parameters` string array and an `enums` record of string arrays).
- Produces in `load-local-catalogs-port.ts`:
  ```ts
  export type LocalCatalogs = {
    readonly enumCatalogs: readonly EnumCatalog[];
    readonly portTypeCatalogs: readonly PortTypeCatalog[];
    /** One line per file that was ignored: path and reason. */
    readonly problems: readonly string[];
  };
  export interface LoadLocalCatalogsPort { load(): LocalCatalogs; }
  ```
  The application layer must not import adapter types: move `EnumCatalog` and `PortTypeCatalog` (and
  `PortTypeCatalogEntry`) type declarations into `src/domain/catalog.ts` and re-export them from their current
  modules so existing imports keep working.
- Produces: `export class FsLocalCatalogs implements LoadLocalCatalogsPort { constructor(directory: string) }`.
  Reads `<directory>/<build>/enum-options.json` and `<directory>/<build>/port-types.json` synchronously (startup
  only); a folder whose name is not all digits is skipped silently; a missing file is not a problem.
